## 0. 한 줄 정의

> **사내망·무인증 로컬/사내 서버 전제로 만든 현 제품을, 공개 URL에 접속해 기획자들이 직접 가입·로그인해
> 쓰는 멀티테넌트 서비스로 연다. 편집기·뷰어·타입·산출물(단독 HTML)은 그대로 살리고, 서버 계층만
> Vercel 서버리스 + Supabase(Postgres·Storage·Auth)로 이식한다.**

검증 질문: **"기획자가 공개 URL에 가입·로그인해서, 자기 목업을 올리고 편집하고 단독 HTML로
내보낼 수 있는가. 그리고 남의 데이터에는 닿을 수 없는가."**

### 왜 지금 (실수요 발생)

- 가능성 타진을 넘어 **공개 URL에 기획자들이 실제로 접속해 쓰는 환경**을 만든다.
- 이는 PRD §7.2 SSO/인증 도입 조건 ①("프로젝트가 여러 사람·부서로 확산되어 소유권 정리 필요")의
  **실수요 발생**이다. 그간 YAGNI로 미뤄둔 DB·인증을 정당하게 앞당긴다.
- 단계(stage) 레벨의 방향 전환이므로 개별 이슈가 아니라 이 킥오프가 진실의 원천이고, GitHub은
  엄브렐라 이슈 #34 + 워크스트림 하위 이슈로만 추적한다.

### 핵심 아키텍처 차이 (현 제품 ↔ 공개판)

| | 현 제품 (파일 기반 Express) | 공개판 (Vercel + Supabase) |
|---|---|---|
| 배포 | 사내망 상주 서버 | 공개 인터넷 서버리스(Vercel) |
| 인증 | 없음 (사내망 전제, NFR-01) | Supabase Auth — Google OAuth + 이메일 매직링크(D1) |
| 격리 | 비추측 프로젝트 ID(nanoid) | 소유자별 RLS 격리(owner_id = auth.uid) |
| 메타·spec 저장 | `data/projects/{id}/spec.json` | Postgres `projects.spec` (JSONB 통짜) |
| 목업 파일 | 디스크 `mockup/` (서버 zip 해제) | Storage 버킷 `mockups` — **브라우저 unzip 후 직업로드**(D5) |
| SDK 주입 | 서빙 때 HTML 변조 | **인제스트 때 1회 주입**(D6) → 정적 서빙 |
| 목업 라우팅 | Host 헤더 서브도메인 분기 | **경로 접두** `/m/{id}/*`(D7) |
| 지원 경로 | A(zip)·B(프록시)·D(확장) | **A·D만** — 경로 B(프록시) 제외(D2) |

## 1. 범위 (확정)

**포함:**

| 포함 | 근거 |
|------|------|
| Supabase Auth 가입·로그인 — Google OAuth + 이메일 매직링크 둘 다(D1) | 공개 멀티테넌트의 전제 |
| Postgres 스키마 + RLS 소유자 격리(§5) + Storage 오브젝트 정책 | 남의 데이터 차단 |
| 스토어 4모듈(project·export·token·paths) → Supabase 어댑터 교체(§8) | 서버 계층 이식의 핵심 |
| 브라우저 unzip + Storage 직업로드 + SDK/`<base>` 주입(D5·D6) | 서버리스엔 영속 디스크 없음 |
| 목업 서빙 `/m/{id}/*` Route Handler(D7) + SPA fallback + 예약 경로 | 정적 목업 격리 서빙 |
| 경로 D 토큰 인증 이식 + 확장 저장 URL 전환 | 확장은 그대로, 저장 대상만 공개 백엔드로 |
| 콘솔 UI Next 이식 + Auth 게이트 | vanilla 콘솔 → Next 페이지(기능 동등) |
| 남용 방어 최소 셋(쿼터·레이트리밋·업로드 검증) | 공개 필수 방어 |
| E2E: 가입→업로드→편집→export→뷰어 공개 시나리오 | 존재 이유 검증(§7 DoD) |

**범위 밖:**
- **경로 B(URL 프록시)** — 공개판 제외(D2). 서버리스·공개판 부적합 + SSRF 표면 소멸. 타입은 하위
  호환 위해 남기되 공개 인테이크에서 거부.
- **팀 공유·역할(editor/viewer)·조직 계층** — v1은 개인 소유 플랫. 실수요까지 유보(YAGNI, §9 밖).
  멤버십을 스키마에 선반영하지 않는다.
- **목업 외부 공유(소유자 아닌 사람에게 편집 화면 노출)** — v1 없음. 여는 순간 신뢰불가 목업 JS의
  교차 테넌트 표면이 다시 열리므로, §7.3 오리진 격리(옵션 1·방법 B) 선행이 필수 조건. 유일한 열린
  질문(§9).
- **절대경로 목업 인제스트 재작성** — v1은 온보딩 제약 문서화로 갈음(§7.1), 재작성은 후속.
- 편집기·앵커·캡처·뷰어·export·마스킹·전이·흐름도는 **무변경**(클라이언트 자산 그대로 생존).

**핵심 재사용(좋은 소식):** 설계 원칙 #3·#4(편집은 라이브·캡처는 클라이언트 브라우저·산출물은 단독
HTML) 덕분에 `shared`·`sdk`·`viewer`가 이미 클라이언트에서 돈다. 공개판은 **서버 계층 이식 + 콘솔
프레임워크 이식**만 새로 필요하고, 제품 재작성이 아니다(§8).

## 2. 불변 vs 재협상 (RFC §2)

**불변 — PRD §1.3 제1원칙 4개는 그대로 유지된다. 개편 대상이 아니다:**
1. 의도는 사람이 입력한다 (LLM 미사용 기본)
2. 사용자는 목업을 수정하지 않는다 (서비스가 SDK 주입)
3. 편집은 라이브, 산출물은 캡처
4. 캡처는 사용자 브라우저에서 (서버 헤드리스 재현 금지) → **산출물 = 단독 HTML, 네트워크 0건**도 불변.

**재협상 — 딱 하나의 전제가 무너지고, 그로부터 파생되는 것만 바뀐다:**
- **NFR-01** "사내망 전제 + 비추측 ID + 무인증" → 공개판에서 **폐기.** 공개 인터넷 + Supabase 인증 +
  소유자 RLS 격리로 대체. (현 file-based 배포에는 유지 — PRD NFR-01 개정에 명시.)
- **PRD §7.2** "인증은 YAGNI" → 조건 ① 충족으로 **해제.**

## 3. 확정된 결정 (RFC §3 — D1~D8)

| # | 결정 |
|---|------|
| D1 | **완전 공개 가입 + 단일 인증.** SSO 없음. **Google OAuth + Supabase 이메일 매직링크 둘 다 제공**(사용자 선택). Supabase Auth가 두 provider를 한 세션 체계로 통합 |
| D2 | **경로 B(URL 프록시) 공개판 제외.** 서버리스·공개판 부적합 + SSRF 표면 소멸. 공개판은 경로 A(zip)+D(확장)만 |
| D3 | **호스팅은 서버리스만 → Vercel 확정.** 상주 컨테이너 불가 |
| D4 | **데이터·인증·저장은 Supabase.** Postgres(메타·spec) + Storage(목업·asset) + Auth |
| D5 | **zip 해제를 브라우저로 이관.** 클라이언트가 unzip → 파일별 Storage 직업로드 → manifest를 API에 통보 |
| D6 | **SDK 주입은 인제스트 시점 1회 — 클라이언트가 브라우저에서 수행.** unzip과 함께 SDK 태그·`<base>` 삽입한 주입본을 Storage에 올리고, 서버는 검증만. 이후 서빙은 정적 |
| D7 | **목업 격리는 경로 접두** `/m/{id}/...`, **v1은 콘솔과 같은 오리진**(옵션 2). 신뢰불가 목업의 오리진 격리(옵션 1·방법 B)는 §7.3 승격 경로로 유보 |
| D8 | **프레임워크는 Next.js**(콘솔 UI + API 라우트 + 미들웨어 + Supabase Auth 연동) |

## 4. 목표 아키텍처

```text
┌────────────────────────────────────────────────────────────┐
│  Vercel (Next.js)                                           │
│  ├─ 콘솔 UI (기존 vanilla 콘솔 → Next 페이지로 이식)          │
│  ├─ 미들웨어: /m/{id}/* 인증·리라이트 → Route Handler 스트림  │
│  ├─ 예약 경로: /__mockspec/sdk.js · /__mockspec/api/* (§6)   │
│  └─ API 라우트 (서버리스 함수)                                │
│       업로드 인테이크 · spec GET/PUT · asset · export · 토큰   │
└───────────────┬───────────────────────────┬────────────────┘
                │                           │
        ┌───────▼────────┐          ┌───────▼──────────┐
        │ Supabase        │          │ Supabase Storage │
        │  Auth (D1)      │          │  단일 버킷 mockups │
        │  Postgres       │          │  projects/{id}/   │
        │   projects/     │          │    mockup/**      │
        │   tokens/exports│          │    assets/**      │
        │   + RLS 격리     │          │  (비공개·RLS)      │
        └─────────────────┘          └──────────────────┘
```

- **예약 경로는 루트 레벨 필수**: 주입된 SDK 로더가 절대 경로(`/__mockspec/sdk.js`)·transport가
  `/__mockspec/api`라 `<base>`·`/m/{id}/` 접두와 무관하게 콘솔 루트에 존재해야 한다. 없으면 경로 A
  목업이 SDK 404로 편집 불가(RFC §6 Codex P1).

## 5. 데이터 모델 → Postgres 스키마 (RFC §5)

`shared/types.ts`의 `SpecProject`는 **그대로 JSONB 1컬럼**으로 넣는다(정규화 안 함 — "단순·범용").
`spec` JSONB가 **유일한 진실의 원천**이고, 최상위 `name`·`updated_at`은 목록 조회·정렬용 **파생 투영**이다.
RLS만으로는 소유자가 파생 컬럼을 spec과 다르게 갱신하는 걸 못 막으므로 **DB 트리거로 spec에서 강제
동기화**한다.

핵심 계약(전체 SQL은 RFC §5):
- `projects(id pk, owner_id, name*, spec jsonb, created_at, updated_at*)` — `*`는 트리거 파생.
  RLS `owner_id = auth.uid()`.
- `project_tokens`·`project_exports` — 하위 테이블도 RLS, 부모 `projects` JOIN으로 소유자 격리.
- **Storage 오브젝트 RLS(별도·필수)**: Postgres 테이블 RLS는 `storage.objects`를 제약하지 않는다.
  단일 버킷 `mockups`의 `projects/{id}/mockup/**`·`projects/{id}/assets/**` 프리픽스로 통일하고,
  경로 첫 두 세그먼트 `projects/{id}`의 소유권을 검증하는 버킷 정책(insert/select/update/delete)을 건다.
  **버킷은 비공개**(public read off).
- `ownerLabel`(자유 텍스트)은 **표시용**으로 유지, 실제 소유·권한은 `owner_id`.
- `MockupSource` union의 `proxy`는 공개판 코드 경로에서 제거(D2) — 타입은 남기되 인테이크 거부.
- **권한 모델 v1**: 프로젝트는 생성자 단독 소유(개인 소유 플랫). 팀 공유·역할·조직은 후속(§9 밖).

## 6. 플로우별 서버리스 함수 (RFC §6)

| 함수 | 동작 |
|------|------|
| `POST /api/projects` | 인증 확인 → `projects` 행 생성(owner_id=auth.uid) |
| **업로드(경로 A)** `POST /api/projects/{id}/mockup:complete` | **서버는 파일을 만지지 않는다(D5·D6).** 클라이언트가 브라우저에서 unzip + SDK 태그 주입 + `<base>` 삽입까지 완료한 주입본을 Storage에 올리고, 서버는 manifest 검증(엔트리 존재·주입 태그 유무·경로 안전성)만 |
| **목업 서빙** `/m/{id}/*` (**Route Handler**, 미들웨어 아님) | **소유자 인증 경유(v1) — 익명 접근 없음.** 미들웨어는 인증·리라이트만(Edge 미들웨어는 본문 스트리밍 불가), Route Handler가 소유권 검증 후 비공개 Storage에서 스트림. **SPA history fallback**: 확장자 없는 미존재 경로는 프로젝트 `index.html`로 폴백(FR-ONB-04·현 `serve.ts` 회귀 방지) |
| **spec GET/PUT** `/api/projects/{id}/spec` | 전체 교체 PUT 유지. asset GC(ID-11)는 Storage 삭제로 이식 |
| **asset** `POST/GET /api/projects/{id}/assets` | 비공개 Storage read/write. 브라우저 직접 업로드는 Storage 오브젝트 RLS(§5)가 소유권 강제. 경로 D는 토큰 인증 |
| **export** `POST /api/projects/{id}/export` | 기존 `buildExportHtml`+뷰어 번들 재사용. asset을 Storage에서 fetch해 인라인. **기본은 완성 HTML을 응답 본문으로 반환**(현 클라이언트 계약 — SDK는 응답 본문을 HTML로 다루고, 확장은 이 엔드포인트를 `chrome.downloads`로 받는다). 큰 산출물만 Storage에 쓰되, **signed URL을 그냥 돌려주면 두 클라이언트가 HTML 대신 URL 응답을 저장/소비해 깨진다(Codex P1)** → **다운로드 핸드오프 명시**: ⓐ 같은 엔드포인트가 signed URL로 302 리다이렉트해 SDK·확장의 기존 다운로드 경로가 그대로 따라가게 하거나, ⓑ SDK·확장에 signed-URL 분기를 추가한다. 저장소 폴백 사용 전 이 핸드오프가 선행(W5) |
| **토큰(경로 D)** `POST /api/projects/{id}/tokens` | 발급 시 평문 1회 노출, 해시만 저장. 재발급·폐기 |
| **예약(SDK)** `GET /__mockspec/sdk.js` | **루트 레벨 필수.** SDK 번들 서빙 |
| **예약(API 브리지)** `/__mockspec/api/*` | **루트 레벨 필수.** SDK transport의 same-origin `/__mockspec/api` → `/api/projects/*` 리라이트 |
| **auth** | Supabase Auth 콜백(D1) |

- 함수 시간·크기 한계는 zip 해제(브라우저 이관)·export 산출물(Storage+signed URL)로 회피. 개별
  함수는 짧은 read/transform/write만.

## 7. 경로 격리(D7)·보안 경계·승격 경로 (RFC §7)

### 7.1 경로 격리 메커니즘
- `/m/{id}/` 접두 아래 서빙. **미들웨어는 인증·리라이트만**, 파일 스트리밍은 **Route Handler**(Edge
  미들웨어는 비공개 Storage 본문 스트리밍 불가).
- **상대 경로**: 인제스트 시 `<head>`에 `<base href="/m/{id}/">` 주입. **기존 `<base>`가 있으면
  교체/재작성**(브라우저는 첫 base만 인정 — 단순 추가 금지).
- **SPA history fallback(FR-ONB-04 — 회귀 금지)**: 확장자 없는 미존재 경로는 프로젝트 `index.html`로
  폴백. 현 `serve.ts` 동작을 Next 이식 시 반드시 보존.
- **알려진 제약**: 절대 루트 경로(`/assets/app.js`)를 쓰는 목업은 접두 밖으로 나가 깨진다 →
  **온보딩 제약으로 문서화**("빌드 base path를 프로젝트 경로에 맞추거나 상대 경로로 빌드"). 인제스트
  시 절대경로 재작성은 후속.

### 7.2 신뢰불가 목업의 오리진 경계
- **문제**: 공개 ZIP은 임의 JS를 담은 동작 웹앱이다. 콘솔/API와 같은 오리진에서 서빙하면 목업의 JS가
  same-origin으로 인증 세션을 달고 `/api`에 요청할 수 있다 — 사소한 문제가 아니라 **인증 경계**.
- **v1 완화(채택 — 옵션 2)**: 목업 서빙을 소유자 인증 경유로 한정(익명 접근 없음) → 남의 악성 목업을
  피해자가 못 열고 RLS가 타 소유자를 막으므로 **교차 테넌트 공격은 차단**. 남는 위험은 자기 계정
  범위(자기가 올린 신뢰불가 ZIP의 self-XSS/CSRF급) → **"자기 팀이 빌드한 믿을 수 있는 ZIP만 업로드"
  사용 제약 문서화**.
- **v1 전제**: 내부 기획자가 자기(팀) 목업만 올린다. 외부 공유(§9)는 v1에 없다.

### 7.3 승격 경로 — 옵션 1 (방법 B, 무료 오리진 격리)
**§9 외부 공유를 열기 전 반드시 선행.** 신뢰불가 목업을 콘솔/API와 다른 오리진에서 서빙:
- 오리진 **1개만 추가**(목업↔목업 격리 불필요 — usercontent 오리진엔 API·세션이 없다). Vercel Hobby
  프로젝트 2개(`*-console` / `*-usercontent`)로 **도메인 구매 없이** 실현, `vercel.app`은 PSL 등재라
  쿠키 공유도 차단.
- **인증 배관**: 오브젝트 단위 서명 URL로는 상대 자산·청크가 인가 안 됨 → usercontent 오리진에 Route
  Handler + **프로젝트 단위 단기 capability**로 전체 오브젝트 인가.
- **대가**: 경로 A 편집 SDK의 same-origin 저장이 막혀 **CORS+토큰 저장**으로 전환(경로 D가 이미 쓰는
  패턴).

### 7.4 오리진 공유 부작용(v1)
프로젝트 간 localStorage/쿠키 공유(같은 오리진). 정적 목업이라 실제 충돌은 드물다. 7.3 승격 시 함께 해소.

## 8. 코드 영향 범위 — 무엇이 살고 무엇이 이식되나 (RFC §8)

| 패키지 | 개편 영향 |
|--------|-----------|
| `shared` (타입 계약) | **거의 그대로 생존.** `MockupSource`에서 proxy 경로 배제 정도 |
| `sdk` (Preact/Shadow DOM 편집기) | **그대로 생존** — 저장 API 엔드포인트 URL만 조정 |
| `viewer` (단독 산출물 런타임) | **그대로 생존** |
| `server` (Express) | **서버리스 함수 / Next API 라우트로 재작성.** 스토어 4모듈이 이미 격리돼 Supabase 호출로 교체가 국소적. `serve.ts`(디스크 서빙)·`proxy.ts`(제거)·unzip(브라우저 이관)이 주요 변경 |
| 콘솔 UI | vanilla → Next 페이지 이식 (기능 동등) |

→ **제품 재작성이 아니라 "서버 계층 이식 + 콘솔 프레임워크 이식".** 편집기·뷰어·타입은 보존.

> **레포 보존 원칙(사용자 제약, 2026-07-22)**: 기존 로컬 베이스 레포는 무손상 유지된다. 개편은 이
> 레포의 장기 브랜치 `open-service` 위에 **추가/이식으로만** 쌓고, 레포 파기·새 레포 생성은 없다.
> 기존 `data/` 런타임 데이터는 새 Supabase로 옮기지 않고 빈 DB로 시작한다(§9-3 결정, 데이터 폐기이지
> 코드/레포와 무관).

## 9. 열린 질문 (유일)

**목업의 외부 공유 여부.** v1은 목업 서빙을 소유자 인증 경유로 확정(익명 접근 없음). 소유자가 아닌
사람에게 편집 화면을 보여줄 필요가 생기면 — 링크 공유(비추측 토큰)·읽기 전용 뷰어 등 — 별도 설계.
**그리고 이때 §7.3 오리진 격리(옵션 1·방법 B)를 선행해야 한다** — 공유가 열리면 신뢰불가 목업 JS의
교차 테넌트 표면이 다시 열리기 때문. 현재 공유 수단은 여전히 **단독 산출물 HTML**(§2 불변).

> RFC §9에서 상류·저강도 결정은 전부 확정됐다(인증·권한 모델·데이터 이관·절대경로·경로 D 저장·남용
> 방어·브랜치 전략). 착수를 막는 열린 질문은 위 하나뿐이며, 그마저 v1 범위 밖이다.

## 10. WBS와 완료 기준 (technical-spec §9.2로 이관 — W1~W9)

| # | 작업 | 완료 기준 (AC) |
|---|------|---------------|
| W1 | Supabase 프로젝트·Auth(Google OAuth + 이메일 매직링크)·스키마(§5)·RLS 세팅 | 테이블 3종 + 파생컬럼 동기화 트리거 + Storage 오브젝트 정책(단일 버킷) + 버킷 비공개. 타 소유자 접근이 RLS로 차단됨을 검증 |
| W2 | 스토어 4모듈(project·export·token·paths) → Supabase(Postgres+Storage) 어댑터 교체 | 기존 스토어 인터페이스 유지, 왕복 무손실 |
| W3 | 업로드 인테이크: 브라우저 unzip + Storage 직업로드 + SDK 주입 + `<base>` 삽입/교체(기존 base 처리) | manifest 검증 통과, 주입본에 SDK 태그·단일 `<base>` 존재 |
| W4 | 목업 서빙 `/m/{id}/*` Route Handler(소유권 검증+스트림) + 인제스트 결과 검증 + SPA history fallback(FR-ONB-04) 보존 | 소유자만 열림, 확장자 없는 미존재 경로가 index.html로 폴백, 서빙 시 per-request 변조 없음 |
| W4b | 예약 경로 루트 라우트: `/__mockspec/sdk.js`(SDK 번들)·`/__mockspec/api/*`(→ `/api/projects/*` 리라이트) | 주입 SDK가 `<base>` 무관하게 로드·저장됨(없으면 경로 A 편집 불가 회귀) |
| W5 | spec GET/PUT·asset·export 함수 이식 (asset GC·export 조립 재사용) | 전체 교체 PUT 왕복 무손실, export 산출물 file:// 네트워크 0건. **큰 산출물 Storage 폴백 시 다운로드 핸드오프(§6 ⓐ 302 리다이렉트 또는 ⓑ 클라이언트 분기)로 SDK·확장이 URL이 아닌 HTML을 저장**(Codex P1) |
| W6 | 경로 D 토큰 인증 이식 + 확장 저장 대상 URL 전환 (manifest `host_permissions`에 공개 백엔드 추가) | 토큰 없는 저장 401, 타 프로젝트 토큰 거부, 확장이 공개 백엔드로 저장 성공 |
| W7 | 콘솔 UI Next 이식 + Auth 게이트 | 미인증 접근 차단, 가입·로그인 후 콘솔 기능 동등 |
| W8 | 남용 방어(쿼터·레이트리밋·업로드 검증) — 공개 필수 최소 셋 | 초과 요청 거부, 악성 업로드 형식 거부 |
| W9 | E2E: 가입→업로드→편집→export→뷰어 공개 시나리오 | DoD(아래) 통과 |

### 공개 서비스 Definition of Done

새 사용자로 가입한 브라우저 컨텍스트에서:
1. 공개 URL 접속 → **가입·로그인**(Google OAuth 또는 이메일 매직링크)
2. 샘플 SPA 목업(zip) 업로드 → 브라우저 unzip + Storage 업로드 + SDK 주입 완료
3. `/m/{id}/`에서 편집 화면 열림(소유자 인증 경유) → 화면 2개 등록·어노테이션 각 2개·설명 입력
4. export → 산출물 HTML을 **새 브라우저 컨텍스트에서 file://로 오픈**
5. 검증: 화면 전환·마커 4개 위치(≤2px)·설명 일치·**네트워크 요청 0건**
6. 격리 회귀: **다른 사용자로 로그인**해 1번 사용자의 프로젝트 spec·목업·asset에 접근 시 RLS로 차단(403/빈 결과)
7. 예약 경로 회귀: 주입 SDK가 `/__mockspec/sdk.js`로 로드되고 저장이 `/__mockspec/api`로 성립

통과 + **실사용 1회**(기획자가 공개 URL로 기획서 1부 완성) 판정을 §11에 기록하면 open-service v1 종료.
