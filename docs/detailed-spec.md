## 1. 제품 구성 요소 개요

사용자가 만나는 화면은 3개다:

| 화면 | 접근 | 역할 |
|------|------|------|
| **콘솔** | `localhost:4000` (루트 도메인) | 프로젝트 목록·업로드·편집 열기·export |
| **편집기 (SDK)** | `{projectId}.localhost:4000` (목업 위 오버레이) | 장면 선언·어노테이션 작성·캡처 |
| **뷰어 (산출물 HTML)** | `file://` 로컬 파일 | 읽기 전용 기획서 열람 |

### 2.2 동작 상세

| 항목 | 사양 |
|------|------|
| 업로드 | `POST /api/projects` (multipart: zip + name). 성공 시 목록 갱신 + 목업 URL로 이동 링크 제시 |
| 불필요 경로 자동 제외 | zip 안에 `node_modules/`, `.git/`, `__MACOSX/`, `.DS_Store`, 소스맵(`*.map`, 설정으로 포함 가능) 등이 들어 있으면 해제 시 자동 스킵. 업로드 결과에 "제외됨: node_modules (1,204개 파일)" 형태로 표시 (technical-spec §3.2) |
| 최상위 폴더 자동 언랩 | `dist` 폴더를 통째로 압축해 zip 루트가 `dist/`인 경우, 공통 최상위 디렉토리를 자동으로 벗겨 루트로 승격. 업로드 결과에 "최상위 폴더 'dist/'를 벗겨 해제했습니다" 형태로 표시 (technical-spec §3.2) |
| 업로드 안내 문구 | "빌드 결과물 폴더(dist 등)만 압축해주세요. node_modules가 포함되면 파일이 커져 업로드가 거부될 수 있습니다 (제한 200MB — 압축 파일 기준)" |
| 업로드 실패 | 200MB 초과: "파일이 너무 큽니다 (최대 200MB). node_modules 등을 제외하고 빌드 결과물만 압축해주세요". zip 아님/해제 실패: "zip 파일을 확인해주세요". (제외 처리·최상위 폴더 언랩 후) index.html 없음: "빌드 산출물 루트에 index.html이 필요합니다" |
| 편집 열기 | 새 탭으로 `http://{projectId}.localhost:4000/` 오픈 |
| 내보내기 | `POST /api/projects/:id/export` → .html 파일 다운로드. 스냅샷 없는 장면이 있으면 다운로드 전 경고: "N개 장면에 스냅샷이 없습니다. 산출물에 플레이스홀더로 표시됩니다. 계속할까요?" |
| 삭제 | 확인 다이얼로그 1회 ("프로젝트와 모든 장면·어노테이션이 삭제됩니다. 되돌릴 수 없습니다." — 작성자 라벨이 있으면 다이얼로그에 프로젝트명과 함께 표시해 오삭제 방지). 확인 책임은 콘솔 UI에 있다 |
| 작성자 라벨 [T29] | 세 생성 폼 공통 "작성자" 입력(선택, 표시용 — 인증 아님, POL-M09). 카드 메타에 표시 |
| 산출물 이력 요약 [T29] | 카드 메타에 "내보내기 N회 (마지막 날짜)" — 목록 응답의 `exportCount`·`lastExportAt` (technical-spec §6.3). 0회면 미표시 |
| 재업로드 [S2 검토] | S1은 프로젝트당 zip 1회 업로드. 목업 갱신은 새 프로젝트로 안내 |

"S2 이후 검토" 안내만).

[S2.5] 3번째 선택지 **[내 화면에서 편집 (확장)]** 추가 (pathD 킥오프 §3): 선택 시 경로 D

## 3. 편집기 (SDK)

### 3.1 진입과 레이아웃 (FR-EDT-01)

- 목업 로드 시 SDK는 **우측 하단 플로팅 버튼(FAB)만** 표시. 목업 첫인상을 해치지 않는다.
- FAB 클릭 → 편집 UI 활성화:
  - 우측 360px 패널이 `position: fixed`로 도킹
  - `document.documentElement`에 `margin-right: 360px` 적용 (목업 레이아웃 축소)
  - 전체 UI는 Shadow DOM 안 → 목업 CSS와 완전 격리
- SDK 루트 요소에 `data-mockspec-root` 마킹 (캡처 시 제외 대상 식별).

```
┌─────────────────────────────────────────────┬───────────────┐
│                                             │ 패널 (360px)   │
│   목업 (margin-right로 축소)                 │ ┌───────────┐ │
│                                             │ │저장됨 ✓    │ │
│   [검색창 ①]  [로그인 ②]                     │ │[미리보기|편집]│
│                                             │ ├───────────┤ │
│   ┌──────────────┐                          │ │장면: 홈 ▾  │ │
│   │  상품 목록    │                          │ │[+ 현재 화면을│
│   │  [담기 ③]    │                          │ │  장면으로]  │ │
│   └──────────────┘                          │ ├───────────┤ │
│                                             │ │① 검색어 입력│ │
│                                             │ │② 로그인 버튼│ │
│                                             │ │③ 장바구니   │ │
└─────────────────────────────────────────────┴───────────────┘
```

### 3.2 모드 정책 (FR-EDT-02)

모드는 **2개뿐**이다. 예외 모드를 만들지 않는다.

| 모드 | 목업 클릭 | 마커 | 용도 |
|------|----------|------|------|
| **미리보기** | 원래대로 동작 (라우팅, 모달 등) | 표시됨 (클릭 시 패널 항목으로 스크롤) | 목업 상태 조작, 장면 만들 준비 |
| **편집** | capture 단계에서 차단 → 어노테이션 부착으로 동작 | 표시 + 부착 가능 | 어노테이션 작성 |

- 토글: 패널 상단 스위치, 단축키 `Alt+Shift+E`
- **금지**: "편집 모드에서 Ctrl+클릭하면 목업으로 통과" 같은 예외. 혼동의 원인이므로 만들지 않는다. 목업을 조작하려면 반드시 미리보기 모드로 전환한다.

### 3.3 어노테이션 부착 시퀀스 (FR-EDT-03)

```
편집 모드에서:
1. 마우스오버 → 대상 요소 하이라이트 (outline, Shadow DOM 오버레이로 그림)
2. 클릭 → 목업의 원래 클릭 차단 (capture 단계 preventDefault + stopPropagation)
3. 대상 요소에 현재 장면 어노테이션이 이미 있으면 → 그 어노테이션 선택 (생성 아님)
   - 같은 요소에 하나 더 달려면 Shift+클릭
4. 없으면(또는 Shift+클릭) 현재 장면에 Annotation 생성:
   - 번호: 현재 장면 내 다음 번호 자동 부여
   - 앵커: selector + text + attrs + rect 자동 생성 (technical-spec §4)
5. 요소 우상단(+markerOffset)에 숫자 마커 렌더
6. 패널의 해당 항목이 열리며 title 입력란에 자동 포커스
7. 입력 → 500ms 디바운스로 자동 저장
```

**전제 조건**: 현재 장면이 없으면(장면 0개) 요소 클릭 시 "먼저 장면을 등록해주세요" 안내 + [+ 현재 화면을 장면으로] 버튼 강조. 어노테이션은 항상 특정 장면에 소속되어야 한다.

**부착 대상 선정 (ID-08)**: 클릭 지점에서 가장 가까운 인터랙티브 조상(a, button, input 등)을 잡고, 없으면 클릭된 요소 그대로. 부모로 확장하는 별도 조작은 없다 — 컨테이너에 달려면 컨테이너 여백을 클릭한다. 같은 요소에 중복 부착은 Shift+클릭으로 허용 (정상/에러 두 설명 등) — 일반 클릭은 기존 어노테이션 선택. 겹친 마커는 드래그로 옮긴다 (§3.5).

### 3.4 어노테이션 편집 항목

| 필드 | UI | 사양 |
|------|-----|------|
| number | 읽기 전용 | 장면 내 1부터 자동 부여 |
| title | 한 줄 입력 | 필수에 준함 (비어 있으면 패널·뷰어에서 "(제목 없음)" 표시) |
| description | 여러 줄 입력 | 마크다운 허용 (뷰어에서 렌더) |
| policyRefs | 태그 입력 | "POL-014" 등 자유 입력. S1은 저장·표시만 (링크 아님) |
| transition [S2] | 장면 선택 드롭다운 + 조건 텍스트 | "성공 시 → 주문완료" 형태 |
| 삭제 | 항목 내 버튼 | 확인 1회. 기존 번호는 재정렬하지 않는다. 새 번호는 현재 최대 번호+1이므로 중간 결번은 유지하고 끝 번호만 재사용 가능 |
| 미작성(빈) 어노테이션 | 자동 표시 + 정리 버튼 | title·description 모두 빈 어노테이션은 "미작성 핀"으로 유지(요소 먼저 찍고 내용은 나중에 작성하는 워크플로우 지원 — 킥오프 §11 5차 개정). 마커·목록에 구분 스타일 표시, 패널 [빈 어노테이션 정리] 버튼으로 일괄 삭제(확인 1회, 끝 번호 재사용 가능) |

### 3.5 마커 렌더·유지 정책 (FR-EDT-04)

- 기본 위치: 앵커 재해석 결과 요소의 **우상단**
- **드래그 이동**: 편집 모드에서 마커를 드래그해 위치 조정. 저장값은 기본 위치 기준 **상대 오프셋**(`markerOffset`, px) — 재해석이 요소를 다시 찾아도 오프셋을 더해 렌더하므로 마커는 요소를 따라간다. 뷰어도 동일 오프셋 적용. 클릭(선택)과 드래그는 이동 임계값으로 구분
- 재해석 트리거: `MutationObserver` + `ResizeObserver`, 300ms 디바운스
- 재해석 단계:
  1. selector로 탐색 → 성공 시 그대로
  2. 실패 시 text/attrs 시그니처로 재탐색 → 성공 시 **selector 자동 갱신** 후 렌더
  3. 그것도 실패 시 rect(뷰포트 비율 좌표) 위치에 **"위치 불확실" 스타일(점선)**로 렌더
- 원칙: 마커가 **조용히 사라지게 두지 않는다.** 불확실하면 불확실하다고 보여준다.
- **패널 선택 스크롤 추종** (이슈 #8): 패널 목록에서 어노테이션을 선택하면 앵커 재해석 결과 요소를 `scrollIntoView({block:'center', inline:'center'})`로 뷰포트 중앙에 표시한다 — 내부 overflow 컨테이너 포함, 넓은 고정폭(1920px+) 페이지에서 뷰포트 밖 마커 조정의 스크롤 왕복 제거. rect fallback 상태면 저장된 rect 좌표로 `window.scrollTo`. 마커·목업 요소 클릭에 의한 선택(이미 뷰포트 안)과 이미 선택된 항목의 재클릭(편집 중 재정렬 방지)은 스크롤하지 않는다.
  - **스크롤 스페이서**: 도킹 margin-right는 고정폭 페이지의 스크롤 범위를 늘리지 못해 문서 오른쪽 끝 패널 폭(360px) 띠가 최대 스크롤에서도 패널에 가린다(Chromium 실측: 루트 margin/padding 모두 scrollWidth 불변). 추종 시 불가시 스페이서(`data-mockspec-scroll-spacer`, 캡처 제외 마킹 `data-mockspec-root` 겸장)를 본문에 두어 콘텐츠 폭+360px까지 스크롤을 확장하고, 패널을 닫으면 제거한다. 도킹 리플로우로 콘텐츠가 패널에 안 가리는 페이지에서는 스크롤을 만들지 않는다. 앵커 rect 비율의 분모는 스페이서를 제외한 콘텐츠 크기(`contentScrollSize`)라 편집·산출물(스냅샷) 간 좌표 계약이 유지된다.
- **마커는 현재 장면 소속 어노테이션만 렌더한다** (ID-09). 라우트↔장면 자동 매칭 로직은 만들지 않는다.
- 목업 라우트 이동 후 복귀 시 마커 복원 (현재 장면의 어노테이션 재해석).

### 3.6 장면 관리 (FR-EDT-05, 06)

**장면 등록**:

```
1. (미리보기 모드에서) 작성자가 목업을 원하는 상태로 조작 — 메뉴 열고, 모달 띄우고
2. 패널의 [+ 현재 화면을 장면으로] 클릭
3. Scene 생성: title = 빈 값 — 목록의 인라인 입력으로 사용자가 직접 명명
   (기본값 document.title은 철회 — SPA는 <title>이 불변이라 모든 장면에 같은 무의미한
   제목이 붙음. 킥오프 §11 8차), route = 현재 pathname+search+hash,
   표시 코드 = 다음 SCR-### (생성 순, 영구 불변 — output-standard §1.2)
4. 즉시 캡처 시도 (§3.7) → 성공 시 snapshotAsset 저장
5. 패널이 해당 장면으로 전환. 이후 부착하는 어노테이션은 이 장면 소속
```

**장면 필드**: title(수정 가능), stateNote("모달 열림 상태" 등 선택 입력), order(패널·뷰어 정렬 기준, 드래그 또는 위/아래 버튼으로 조정).

**현재 장면 규칙 (ID-09)**: 패널에서 선택된 장면이 곧 현재 장면이다. 라우트와 자동 연동하지 않는다 — 미리보기 모드에서 다른 라우트로 이동해도 현재 장면은 유지되고, 라우트 변경 배너만 뜬다. 장면 등록 시 그 장면이 자동으로 현재 장면이 된다. (자동 추론 금지 원칙 POL-M03의 연장: 현재 장면도 사람이 고른다.)

**장면 삭제**: 소속 어노테이션도 함께 삭제. 확인 다이얼로그 1회 ("이 장면과 어노테이션 N개가 삭제됩니다").

**장면 재캡처**: 장면 항목의 [다시 캡처] 버튼 — 현재 화면 상태로 스냅샷 교체. (목업 상태가 그 장면과 다를 수 있으므로 "현재 보이는 화면으로 스냅샷을 교체합니다" 확인 1회.)

**SPA 라우트 변경 감지** (FR-EDT-06):

- history API 후킹으로 라우트 변경 감지 시 패널 상단에 배너: **"새 장면으로 등록할까요? [등록] [무시]"**
- 자동 생성 금지. 이것은 기존 크롤러 실패에서 얻은 교훈의 구현 지점이다.
- 같은 라우트로의 반복 이동은 배너를 다시 띄우지 않는다 (세션 내 라우트별 1회).

### 3.7 장면 캡처 UX (FR-EDT-08, 09)

- 캡처 실행 중: 해당 장면 항목에 스피너 (수 초 걸릴 수 있음 — 이미지 data URI화)
- 성공: 장면 항목에 캡처 시각 표시. 스냅샷은 **레이아웃·구조 재현**이 목적 — 폰트는 시스템 대체, 비디오·오디오는 영역만 유지(콘텐츠 미임베드, 킥오프 §11 11차)
- 실패: 에러 토스트 + 장면 항목에 **"캡처 실패 — 재시도"** 배지. 어노테이션 작성은 계속 가능 (캡처는 export에만 필요하다)
- 스크린샷 fallback은 [S2] (fallback 품질 문제로 S1이 늘어지는 것 방지 — 킥오프 스펙 §7.3의 의도적 절단)

### 3.8 저장 상태 표시 (FR-EDT-07)

패널 상단에 상시 표시:

| 상태 | 표시 | 조건 |
|------|------|------|
| 저장됨 | `저장됨 ✓` | 마지막 PUT 성공 |
| 저장 중 | `저장 중…` | 디바운스 대기 또는 요청 진행 |
| 오프라인 | `오프라인 — 로컬 보관 중` | PUT 실패, localStorage 큐에 적재됨 |

오프라인 큐(`mockspec:pending:{projectId}`)는 온라인 복귀·재방문 시 자동 재전송.

### 3.9 편집 화면 내보내기 (킥오프 §11 6차 개정)

- 패널 하단 고정 영역에 **[내보내기 (HTML)]** 버튼. 콘솔 내보내기(§2.2)와 동일 규칙:
  스냅샷 없는 장면 N개면 확인 다이얼로그 후 진행, 50MB 초과 경고 헤더는 버튼 아래 힌트로 표시.
- `POST /__mockspec/api/projects/:id/export`(same-origin 프록시) → `Content-Disposition`
  파일명 유지한 채 즉시 다운로드. 프로젝트 로드 전·진행 중에는 버튼 비활성.

### 3.10 전이 지정과 흐름도 (FR-EDT-10, FR-EXP-06 — 2026-07-12 착수 확정)

- 어노테이션 편집 폼에 "이 요소 조작 시 이동할 장면" 드롭다운 + 조건 텍스트("성공 시" 등)
  - 드롭다운은 **다른 장면만** 나열한다 — 전이는 정의상 장면 *간* 연결(PRD §2 용어)
  - 전이 대상 장면이 삭제되면 그 장면을 가리키는 transition은 함께 제거한다 (dangling 방지)
- scenes + transitions = 방향 그래프 → 산출물에 흐름도 자동 렌더 (자체 경량 SVG —
  2026-07-12 Mermaid에서 변경, s1-kickoff §11 7차: 단독 HTML에 ~3MB 번들 내장 회피)
- 흐름도는 사람이 입력한 전이만 그린다. 추론으로 채우지 않는다 — 빈 그래프면 빈 대로 보여준다

### 3.11 LLM 디스크립션 초안 제안 [S3] (FR-EDT-13) — 옵트인

- **기본 OFF.** 프로젝트 설정(콘솔)에 "AI 초안 제안" 토글을 두고, 켠 프로젝트에서만 어노테이션 편집 폼에 [초안 제안] 버튼이 노출된다.
- OFF 상태에서는 LLM API 호출이 코드 경로상 발생하지 않는다 (버튼 숨김이 아니라 기능 자체 비활성).
- ON일 때 동작: 현재 장면 컨텍스트 + 클릭한 요소 정보 → 한두 문장 초안을 description 입력란에 **제안으로만** 채움. 사람이 수정·확정하기 전에는 저장되지 않음.
- 제안 근거 데이터(장면 스냅샷 일부)가 외부 LLM API로 나가므로, 토글 옆에 이를 명시하는 안내 문구를 붙인다.

### 3.12 마스킹 편집 [S2] (FR-EDT-11, 킥오프 스펙 §5)

- 용도: 화면에 보이는 실데이터(고객명, 이메일 등)가 산출물로 사외 반출되는 것 방지 —
  프록시 목업(스테이징)은 실데이터를 담을 수 있어 S2에서 필수 (technical-spec §7.2)
- **방식: 프로젝트 단위 find→replace 규칙 목록** (`maskingRules`). 콘솔의 프로젝트 항목에
  [마스킹] 편집 화면 — 규칙 테이블(추가·수정·삭제) + 장면별 적용 미리보기 + [전체 장면에 적용]
- `find`는 **평문 부분 일치만** — 정규식 미지원 (기획자 사용자에게 정규식 오류·과잉 매칭
  디버깅 비용이 이득보다 큼). 요소 클릭 방식의 스냅샷 직접 편집기도 기각 — 마스킹 대상은
  "반복 등장 문자열"이라 찾기-바꾸기가 자연스럽고, 클릭 편집기는 별도 에디터 규모
- 치환 대상은 스냅샷 HTML의 **텍스트 노드와 속성값(`value`, `placeholder`, `title`, `alt`,
  `aria-label`)만** — 태그명·구조 불변
- **마스킹본 생성은 콘솔(브라우저)에서**: 원본 스냅샷 fetch → `DOMParser` 파싱 → 규칙 적용 →
  asset 업로드 → `Scene.maskedSnapshotAsset` 기록. 서버는 HTML을 파싱하지 않는다 (캡처와
  동일 원칙 — 서버는 저장·조립만)
- **원본 스냅샷은 보존** — 규칙 변경 시 항상 원본에서 재생성 (재마스킹 가능). 마스킹본 갱신은
  [전체 장면에 적용] 버튼을 눌러야 일어난다는 단순 규칙 (자동 재적용 없음)
- export 시 마스킹본 우선 사용. 규칙이 있는데 마스킹본이 없는(또는 규칙보다 오래된) 장면이
  있으면 확인 다이얼로그: "마스킹이 적용되지 않은 장면 N개가 있습니다. 계속할까요?" —
  콘솔·편집 패널 양쪽 내보내기 진입점에 동일 적용 (§2.2·§3.9)

## 4. 뷰어 (산출물 HTML) (FR-EXP-01~05)

### 4.1 화면 구성

```
┌──────────────────────────────────────────────────────────────┐
│ 주문 개편 목업 기획서    생성: 2026-07-06    장면 3 · 어노테이션 12 │
├────────┬─────────────────────────────────────┬───────────────┤
│ 장면    │                                     │ ① 검색어 입력   │
│ ─────  │   [캡처 스냅샷 — iframe srcdoc]      │   2자 이상 입력 │
│ ▸ 홈    │                                     │   시 자동완성   │
│   검색  │   [검색창 ①]  [로그인 ②]             │ ② 로그인 버튼   │
│   주문  │                                     │   미로그인 시   │
│        │   (읽기 전용, 스크립트 0개)           │   /login 이동  │
│        │                                     │   POL-014      │
└────────┴─────────────────────────────────────┴───────────────┘
```

| 영역 | 사양 |
|------|------|
| 상단 바 | 프로젝트명, 작성자 라벨(있을 때 — T29), 생성 일시, 장면 수/어노테이션 수 |
| 좌측 사이드바 | 장면 목록 (order 순, `SCR-001 로그인` 표기 — output-standard §4). 선택 시 중앙에 해당 장면 표시 |
| 중앙 | `<iframe srcdoc>`에 스냅샷 주입 (base64 디코드). iframe 위 오버레이 레이어에 숫자 마커 — 앵커 재해석은 SDK와 동일 로직(anchor 모듈 공유). 실패 시 rect fallback |
| 우측 패널 | 어노테이션 목록: 번호, title, description(마크다운 렌더), policyRefs 뱃지 |
| 상호작용 | 마커 클릭 ↔ 목록 항목 상호 하이라이트·스크롤 |
| 스크롤 | 셸이 뷰포트 높이에 고정 — 페이지 스크롤 없이 3컬럼 각자 내부 스크롤(중앙은 양방향, 큰 흐름도는 섹션 안에서만). 좁은 화면(≤900px)은 1단 스택 + 페이지 스크롤 |
| 스냅샷 없는 장면 | 중앙 플레이스홀더 + "편집 화면에서 캡처 후 재내보내기" 안내 |
| 전이 링크 | 어노테이션에 transition이 있으면 "→ [SCR-### 장면제목 보기]" 링크 — 클릭 시 해당 장면으로 전환 (실행 대신 이동). 대상 장면이 없으면(비정상 데이터) 링크 미표시 |
| 흐름도 | 헤더 아래 접을 수 있는 섹션에 자체 SVG 흐름도 (output-standard §2 섹션 2 위치). 노드 클릭 시 해당 장면으로 전환. 전이가 하나도 없으면 섹션 자체 생략 |

### 4.2 산출물 파일 원칙

- **단일 .html 파일**, 외부 참조 0개, `file://`에서 완전 동작, 네트워크 요청 0건
- 스냅샷에 `<script>`가 하나도 없음 (캡처 시 검증 로직으로 강제) → srcdoc으로 열어도 실행 위험 없음
- 50MB 초과 시 경고와 함께 진행 (메일 첨부 한계 안내)
- 목업이 나중에 죽거나 바뀌어도 산출물은 그 시점 상태를 보존 — 기획서의 아카이브 속성

| 상황 | 처리 |

| 장면 0개 상태에서 요소 클릭 | 부착 대신 "먼저 장면을 등록해주세요" 안내 (§3.3) |
| 캡처 실패 (canvas/WebGL, CSS-in-JS 등) | 실패 배지 + 재시도. 작성은 계속 가능. export 시 플레이스홀더 (§3.7) |
| 앵커 재해석 전부 실패 | rect 위치에 점선 "위치 불확실" 마커 — 숨기지 않는다 (§3.5) |
| 서버 다운 중 편집 | localStorage 큐 적재 → 재기동 후 자동 반영 (§3.8) |
| 목업 백엔드 사망 | 캡처된 장면은 유효. 새 장면 추가만 불가 — 콘솔·패널에서 별도 처리 없음 (자연 동작) |
| zip에 index.html 없음 | 최상위 폴더 언랩 후에도 없으면 업로드 거부 + 안내 (§2.2) |
| zip 루트가 폴더 한 겹(`dist/` 등) | 공통 최상위 디렉토리 자동 언랩 후 정상 진행 + 결과 안내 (§2.2) |
| zip에 node_modules 등 포함 | 해제 시 자동 제외 + 결과 안내. 단, zip 자체가 200MB 초과면 업로드 단계에서 거부 (제한은 압축 파일 기준) — dist만 압축하도록 안내 (§2.2) |
| zip 내 경로 탈출 시도 (zip-slip) | 경로 정규화 후 프로젝트 디렉토리 밖 기록 거부 (technical-spec §7.1) |
| 산출물 50MB 초과 | 경고 후 진행 (§4.2) |
| 목업 파일 경로와 SDK 예약 경로 충돌 | `/__mockspec/*`는 예약 경로 — 목업 파일보다 우선 (technical-spec §3.2) |
| base가 하위 경로로 박힌 빌드 | 서브도메인 방식이라 대부분 무관하나 콘솔에 안내 문구 (§2.1) |

## 7. 사용자 여정별 수용 기준 (S1)

킥오프 스펙 §10의 WBS AC를 사용자 관점으로 재기술한 것. E2E 시나리오의 원천.

| 여정 | 수용 기준 |
|------|----------|
| J1 목업 등록 | zip 업로드 → `{id}.localhost:4000`에서 목업이 열리고, HTML 소스에 sdk.js 태그가 존재한다 |
| J2 편집 진입 | FAB 클릭으로 패널이 열리고, 목업 CSS와 시각적 간섭이 없으며, 미리보기 모드에서 목업이 정상 조작된다 |
| J3 어노테이션 | 요소 클릭 → 마커 부착 → 설명 입력이 §3.3 시퀀스대로 동작하고, 라우트 이동 후 복귀 시 마커가 복원되며, 요소 텍스트가 바뀌어도 재탐색에 성공한다 (1케이스 이상) |
| J4 장면 캡처 | 장면 추가 시 스냅샷이 업로드되고, 스냅샷 단독으로 브라우저에서 열어 원본과 시각적으로 동일하며, `<script>`가 0개다 |
| J5 오프라인 내구성 | 서버 중단 상태에서 편집한 내용이 재기동 후 자동 반영된다 |
| J6 산출물 | export된 HTML이 `file://`로 열리고, 마커·패널·상호 하이라이트가 동작하며, 네트워크 요청이 0건이다 |
| J7 콘솔 완결성 | 업로드 → 편집 열기 → export 다운로드가 콘솔만으로 가능하다 |
