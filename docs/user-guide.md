# mockspec 사용 가이드 — 세 가지 연결 방식

> 목업을 서비스에 연결하는 방식은 세 가지다. **무엇을 갖고 있느냐**에 따라 하나를 고른다.
> 이 문서는 각 방식의 사용법·동작 원리·제약·적합한 경우를 다룬다.
> (2026-07-12 기준. 실행 환경 준비는 루트 [README.md](../README.md) §1 참조)

## 0. 한눈에 고르기

```
목업이 어디 있나요?
├─ 빌드 결과물(zip)을 만들 수 있다 ──────▶ 경로 A: ZIP 업로드 (가장 단순 — 권장)
├─ 이미 URL로 접근 가능하다 (로그인 불필요) ▶ 경로 B: URL 프록시
└─ 로그인해야 보인다 / 내 브라우저에서만 된다 ▶ 경로 D: 내 화면에서 편집 (확장)
```

| | A. ZIP 업로드 | B. URL 프록시 | D. 내 화면에서 편집 (확장) |
|---|---|---|---|
| **준비물** | 빌드 산출물 zip | 서버가 접근 가능한 URL | Chrome 확장 설치 + 연결 코드 |
| **설치 난이도** | 없음 | 서버 allowlist 설정 1회 | 확장 로드·연결 (아래 §3 상세) |
| **로그인 화면** | — (정적이라 무관) | ✗ 불가 (익명 접근만) | ✓ 가능 (내 세션 그대로) |
| **원본 보존** | 업로드 시점에 고정 | 원본 서버 실시간 반영 | 내 브라우저 화면 실시간 |
| **저장 인증** | 없음 (same-origin) | 없음 (same-origin) | 프로젝트 토큰 (Bearer) |
| **적합한 경우** | 목업 레포가 있고 빌드 가능 | 이미 떠 있는 스테이징·데모 | 사내 시스템, SSO 뒤 화면, 로컬 개발 서버 |

편집(화면·어노테이션·화면 이동)·마스킹·내보내기·산출물은 **세 경로 모두 완전히 동일**하다 (§4~§6).
경로는 "목업을 어떻게 화면에 띄우고 SDK를 누가 주입하느냐"만 다르다.

## 1. 경로 A — ZIP 업로드

### 사용법

1. 목업 프로젝트에서 빌드: `npm run build` → `dist/` 생성 → `zip -r mockup.zip dist`
2. 콘솔(`http://localhost:4000`) → **[ZIP 업로드]** 탭 → 이름 입력 + zip 선택 → 업로드
3. 완료 안내의 **편집 열기 →** 클릭 — 목업이 `{프로젝트ID}.localhost:4000`에서 SDK가 주입된 채 열린다

### 동작 원리

- 서버가 zip을 해제해 프로젝트별 **서브도메인에서 정적 서빙**한다. `dist/` 한 겹 포장은 자동 언랩,
  `node_modules/`·`.git/`·`*.map` 등은 해제 시 자동 제외
- HTML 응답에만 `</body>` 직전 `<script src="/__mockspec/sdk.js">`를 끼워 넣는다 — **zip 원본은 무수정**
- SPA history 라우팅은 fallback(확장자 없는 404 → index.html)으로 동작
- 서브도메인 분리 이유: 목업 간 localStorage/쿠키 격리 + 절대 경로(`/assets/…`) 빌드의 무수정 동작

### 제약

| 제약 | 내용 |
|------|------|
| 빌드 산출물만 | 소스가 아니라 **빌드 결과물**. 루트에 `index.html` 필수 (SSR 전용은 정적 export 필요) |
| 크기 | zip 200MB 이하 (빌드 결과물만 압축 권장) |
| 백엔드 없음 | 정적 서빙이므로 목업이 실 API를 부르면 그 요청은 실패한다 — 목업은 mock 데이터 내장이 전제 |
| 시점 고정 | 업로드 시점의 스냅샷. 목업이 바뀌면 다시 zip 업로드 (프로젝트를 새로 만들어야 함) |

**적합**: 목업 레포를 갖고 있고 빌드할 수 있는 경우. 가장 단순하고 제약이 적다 — 기본 권장 경로.

## 2. 경로 B — URL 프록시

### 사용법

1. (서버 운영자, 1회) 허용 오리진을 env로 등록하고 서버 기동:
   ```bash
   MOCKSPEC_PROXY_ALLOWLIST="mockup.team-a.internal,*.vercel.app" node packages/server/dist/index.js
   ```
   로컬 개발 서버(loopback)를 등록하려면 `MOCKSPEC_PROXY_ALLOW_LOOPBACK=true`도 필요
2. 콘솔 → **[URL 프록시]** 탭 → 이름 + 목업 URL 입력 → 등록
3. **편집 열기 →** — 목업이 프록시 서브도메인에서 SDK 주입된 채 열린다

### 동작 원리

- 서버가 **리버스 프록시**로 원본을 대신 가져와 서브도메인에서 서빙하며 HTML에 SDK를 주입한다
- 주입을 막는 응답 헤더(CSP, X-Frame-Options)는 프록시가 제거, 쿠키는 프록시 오리진으로 재바인딩
- 리다이렉트는 같은 오리진 안에서만 따라간다 — **오리진 밖(외부 IdP 등)으로 나가면 502**
- SSRF 방어: allowlist에 없는 오리진은 등록 거부(deny-by-default), 루프백·메타데이터 IP 차단

### 제약

| 제약 | 내용 |
|------|------|
| **로그인 불가** | 프록시는 **익명으로** 원본을 가져온다. 로그인·SSO가 필요한 화면은 리다이렉트로 튕겨 열리지 않는다 → 그 경우가 바로 경로 D |
| allowlist 필수 | 서버 env에 등록된 오리진만. 등록 실패 시 사유가 콘솔에 표시된다 |
| 서버 도달성 | mockspec 서버가 그 URL에 접근할 수 있어야 한다 (사내망 URL이면 서버도 사내망에) |
| 원본 변경 반영 | 실시간 프록시라 원본이 바뀌면 편집 화면도 바뀐다 — 화면은 동결본이라 안전하지만, 앵커 재탐색이 흔들릴 수 있다 |

**적합**: 이미 스테이징·데모 URL로 떠 있는 목업. zip을 만들 필요가 없다.

## 3. 경로 D — 내 화면에서 편집 (확장) ★ 상세

**"내 브라우저에 보이는 화면 그대로"**를 편집 대상으로 삼는다. 서버는 그 화면에 접근하지
않는다(접근할 수도 없다) — 로그인 세션, 사내망, localhost 전부 커버되는 이유다.
그만큼 준비 단계가 많으니 순서대로 따른다.

### 3.1 동작 원리 (왜 이런 단계가 필요한가)

```
[콘솔]                [Chrome 확장]                         [대상 페이지(내 화면)]
프로젝트 생성  ──▶  팝업에 연결 코드 등록          content script가 바인딩된 오리진에만
+ 토큰 발급          (오리진 ↔ 프로젝트+토큰 바인딩)   SDK <script> 주입 → FAB·편집 패널
                          │
                          ▼
                    background service worker
                    저장·불러오기를 서버로 릴레이 (Bearer 토큰은 여기서만 부착 — 페이지에 토큰 미노출)
                    내보내기는 chrome.downloads로 직접 다운로드 (대용량도 안전)
```

- 서버가 화면을 가져오는 게 아니라 **확장이 내 화면 위에 편집기를 얹는다**. 페이지 CSP와 무관하게 동작
- 익명 저장을 막기 위해 이 경로만 **프로젝트 토큰**으로 저장을 인증한다 (발급 1회 표시, 해시만 서버 보관)
- 동결(스냅샷)도 내 브라우저에서 실행 — 지금 보이는 상태(로그인 후 데이터 포함)가 그대로 굳는다.
  **실데이터가 산출물에 들어가므로 사외 공유 전 마스킹(§5)을 반드시 검토할 것**

### 3.2 설치·연결 (최초 1회)

1. **확장 로드**: Chrome `chrome://extensions` → 우상단 **개발자 모드** ON →
   **압축해제된 확장 프로그램을 로드** → 저장소의 `packages/extension/dist` 폴더 선택
   (`npm run build`가 만들어 둔다. 코드 갱신 후에는 이 화면에서 ↻ 새로고침)
2. **프로젝트 생성**: 콘솔 → **[내 화면에서 편집 (확장)]** 탭 → 이름 입력 → 생성.
   **연결 코드**가 표시된다 → **[연결 코드 복사]** (코드는 프로젝트ID+토큰+서버 주소가 한 줄로 합쳐진 것)
3. **연결**: 대상 페이지 탭을 연 상태에서 확장 아이콘 클릭 → 팝업의 입력란에 연결 코드
   **붙여넣기** → **[연결]**. 바인딩은 **오리진 단위**다 (`https://admin.example.com` 전체에 적용)
4. 대상 페이지를 **새로고침** → 우하단 ✎ FAB가 보이면 연결 성공

연결 코드를 잃어버렸으면: 콘솔 프로젝트 카드의 [연결 코드 복사](같은 브라우저 세션 동안 보관) 또는
**[토큰 재발급]** — 재발급하면 **이전 토큰은 즉시 무효**가 되므로 팝업에 새 코드로 다시 연결한다.

### 3.3 사용 순서

1. 대상 시스템에 **직접 로그인**하고 원하는 화면·상태를 만든다
2. FAB → 패널 → **[+ 현재 화면 등록]** → `✓ 동결됨` 확인 → 어노테이션·화면 이동 편집 (§4)
3. 저장은 자동 (패널 상단 `저장됨 ✓`). 저장이 안 되면 §3.5 트러블슈팅
4. 내보내기: 패널 하단 **[내보내기 (HTML 다운로드)]** → "브라우저 다운로드로 저장을 시작했습니다"
   → 브라우저 다운로드 바에서 파일 확인. (콘솔의 내보내기 버튼도 가능 — 토큰을 물어본다)

### 3.4 제약·주의

| 제약 | 내용 |
|------|------|
| Chrome/Edge 전용 | 편집 환경 자체가 Chrome/Edge 한정 (뷰어 산출물은 어디서나 열림) |
| 서버 주소 | 확장의 `host_permissions`가 `localhost`/`127.0.0.1` 기준 — mockspec 서버를 다른 호스트에 두려면 `manifest.json`의 host_permissions에 추가 후 확장 재로드 필요 |
| 토큰 관리 | 연결 코드에 토큰이 들어 있다 — 코드 공유 = 그 프로젝트 쓰기 권한 공유. 유출 시 [토큰 재발급] |
| 동결 폴백 | 일부 사이트(복잡한 CSS)는 동결이 안전 모드로 폴백된다 — 이때 웹폰트가 시스템 폰트로 대체된 스냅샷이 남는다 (기획서 용도로는 대체로 무방) |
| 무거운 화면 | 고해상도 이미지가 많은 화면은 스냅샷이 커진다 — 동결 시 자동으로 이미지를 WebP·2048px로 최적화하지만, 그래도 크면 화면 수를 줄이는 것이 유일한 수단 |
| 프레임워크 간섭 | 전역 포커스를 관리하는 프레임워크(Nexacro 등)는 자동 방어가 들어 있다. 새로운 간섭 유형을 만나면 증상을 기록해 리포트 |

### 3.5 트러블슈팅

| 증상 | 원인·해결 |
|------|----------|
| FAB가 안 보임 | 팝업에서 이 **오리진**에 연결했는지 확인 → 페이지 새로고침. 확장이 로드·활성 상태인지 확인 |
| 패널에 "불러오기 실패" | 서버 미기동 / 연결 코드의 서버 주소 불일치 / 프로젝트가 삭제됨 |
| `저장됨`이 안 되고 "오프라인 — 로컬 보관 중" | 서버가 죽었거나 토큰이 무효(재발급했다면 새 코드로 재연결). 복구되면 자동 재전송 |
| "동결 실패 — 재시도" 배지 | 배지 클릭으로 재시도. 계속 실패하면 자동 폴백까지 실패한 것 — 화면 단순 상태에서 재시도 |
| 내보내기 후 파일이 안 보임 | 브라우저 다운로드 바·다운로드 폴더 확인 (패널이 아니라 브라우저가 저장한다) |
| 코드 갱신 후 동작이 예전 그대로 | `chrome://extensions`에서 확장 ↻ 새로고침 + 대상 페이지 새로고침 |

**적합**: 로그인/SSO 뒤 화면, 사내 시스템, 내 로컬에서만 도는 개발 서버. 실화면 기반 기획이 필요한 모든 경우.

## 4. 편집 — 세 경로 공통

편집 화면(FAB → 우측 패널)의 모든 기능은 경로와 무관하게 동일하다.

| 동작 | 방법 |
|------|------|
| 화면 등록 | 목업을 원하는 상태로 조작 → **[+ 현재 화면 등록]** → `✓ 동결됨` 확인. 화면 제목은 목록의 입력란에 직접 기입 |
| 다시 동결 | 화면 행의 ⟳ — 화면을 다시 그 상태로 만들고 누르면 스냅샷이 현재 화면으로 교체된다 |
| 어노테이션 부착 | **편집 모드**(Alt+Shift+E)에서 요소 클릭. 이미 마커 있는 요소 클릭=선택, 같은 요소에 하나 더=Shift+클릭 |
| 마커 위치 조정 | 편집 모드에서 마커 드래그 (요소 추적과 공존하는 상대 오프셋으로 저장) |
| **화면 이동 지정** | 어노테이션 폼의 드롭다운에서 **이동할 화면** 선택 + 조건 텍스트("성공 시" 등). 화면이 2개 이상일 때 나타난다 |
| 목업 조작 복귀 | **미리보기 모드**로 전환 (편집 모드에선 목업 클릭이 차단됨) |
| 저장 | 자동 (500ms 디바운스, `저장됨 ✓` 확인). 서버 단절 시 로컬 보관 → 복구 시 자동 반영 |
| 내보내기 | 패널 하단 버튼 또는 콘솔에서 |

**화면 이동과 흐름도에 대해** — 화면 이동("이 요소를 조작하면 → 화면 X로 이동")은 **어노테이션의 속성**이고,
어노테이션 편집은 라이브 편집 패널에서만 한다. 이는 특정 경로의 제약이 아니라 설계 원칙
("편집은 라이브, 산출물은 동결")이다:

- 세 경로 **모두** 편집 패널에서 화면 이동을 지정할 수 있다 — 경로 D 전용이 아니다
- 콘솔은 관리(등록·마스킹·내보내기·삭제)만, 뷰어(산출물)는 읽기 전용 — 여기서 화면 이동을 만들 수 없는 것은 의도
- 입력된 화면 이동은 산출물에서 **프로세스 흐름도**(섹션 2)와 어노테이션 카드의 **"→ SCR-### 보기" 링크**로 렌더된다.
  사람이 입력한 화면 이동만 그린다 — 화면 이동이 하나도 없으면 흐름도 섹션 자체가 생략된다

## 5. 마스킹 — 사외 공유 전 실데이터 치환

스냅샷은 화면 그대로다 — 고객명·이메일 등 실데이터가 있으면 산출물로 새어 나간다.

1. 콘솔 프로젝트 카드 → **[마스킹 편집]** → 규칙 추가 (찾을 문자열 → 치환 문자열, 평문 부분 일치)
2. **[전체 화면에 적용]** → 마스킹본 생성 (원본 스냅샷은 보존 — 규칙을 고치면 원본에서 재생성)
3. 내보내기 — 마스킹본이 우선 사용된다. 규칙보다 오래된 마스킹본이 있으면 확인 다이얼로그가 뜬다

정규식은 지원하지 않는다(의도) — 반복 등장하는 실데이터 문자열을 그대로 넣는다.

## 6. 산출물(기획서 HTML) 읽는 법

- **단독 HTML 1파일** — `file://`로 열리고 네트워크 요청 0건. 슬랙·메일로 파일만 전달
- 상단: 프로젝트명·생성 일시·화면/어노테이션 수
- **프로세스 흐름도**(화면 이동이 있을 때): 노드=화면, 간선 라벨=이동 조건. 노드 클릭 시 해당 화면으로 이동, ▾로 접기
- 좌측 화면 목록(« 로 접기) / 중앙 스냅샷+마커(캡처 시점 뷰포트 크기로 재현, 넓으면 가로 스크롤) /
  우측 어노테이션(마커↔목록 상호 하이라이트, 이동 링크로 화면 이동)
- 뷰어·동결 코드가 갱신된 뒤에는 **다시 내보내기**해야 산출물에 반영된다. 스냅샷 자체의 개선
  (이미지 최적화·캡처 크기 기록)은 **재동결**해야 반영된다

## 7. 어떤 경로를 골라야 할지 아직 모르겠다면

1. **zip을 만들 수 있으면 A** — 가장 단순, 제약 최소
2. A가 안 되고 **로그인 없이 URL로 열리면 B**
3. **그 외 전부 D** — 로그인·사내망·로컬. 준비가 까다로운 대신 커버 범위가 가장 넓다

한 프로젝트는 한 경로에 묶인다. 같은 목업을 다른 경로로 쓰려면 프로젝트를 새로 만든다.
