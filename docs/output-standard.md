## 1. ID 체계

### 1.1 두 층위: 내부 ID와 표시 코드

| 층위 | 형식 | 용도 | 사용자 노출 |
|------|------|------|------------|
| **내부 ID** | `prj_`/`scn_`/`ann_`/`pol_` + nanoid(10) | 참조 무결성, API, 저장 | 노출 안 함 |
| **표시 코드** | `SCR-###`, `POL-###`, 장면 내 번호 ①②③ | 사람이 읽고 부르는 이름 (기획서 본문, 회의, 리뷰 코멘트) | 뷰어·패널에 표시 |

내부 ID는 절대 바뀌지 않고, 표시 코드는 사람의 참조 습관을 위해 존재한다. 두 층위를 섞지 않는다.

### 1.2 표시 코드 정의

| 코드 | 대상 | 부여 규칙 |
|------|------|----------|
| **SCR-###** | 장면(Scene) | 프로젝트 내 **생성 순** 3자리 (SCR-001부터). 장면 생성 시 확정되어 `Scene.code`에 저장. **재부여·재사용 금지** — 장면을 삭제해도 그 번호는 영구 결번. order(정렬)를 바꿔도 코드는 불변 |
| **①②③ (장면 내 번호)** | 어노테이션(Annotation) | 장면 내 1부터 자동 부여. 신규는 현재 남은 최대 번호+1. 기존 번호는 재정렬하지 않아 중간 결번은 유지하고, 끝 번호만 재사용 가능 |
| **SCR-###-N** | 어노테이션 전역 참조 | 장면 코드 + 번호 조합 (예: `SCR-003-2`). 장면을 넘어 어노테이션을 지칭할 때 사용 (전이 설명, 정책 본문, 리뷰 코멘트) |
| **POL-###** | 정책(Policy) [S2] | 프로젝트 내 정책정의서 항목. 생성 순 3자리, 재부여 금지. S1에서는 `policyRefs`에 자유 텍스트로 기입만 (외부 정책 문서 참조 포함) |

SCR·POL 표시 코드는 **이미 공유된 산출물과의 참조 불일치 방지**를 위해 영구 재사용하지 않는다.
어노테이션 번호는 편집 중 마지막 항목 삭제·재생성에서 불필요하게 증가하지 않도록 끝 번호만
재사용한다. 따라서 산출물 버전을 넘어선 영구 참조가 필요하면 표시 번호가 아니라 내부 `ann_*`
ID 또는 산출물 생성 시각을 함께 사용한다.

### 1.3 서비스 문서용 ID (산출물과 구분)

혼동 방지를 위해 명시한다. 아래는 mockspec **서비스 자체를 만들기 위한** 문서 ID이며, 사용자의 기획서(산출물)에는 등장하지 않는다:

| 코드 | 정의 위치 | 대상 |
|------|----------|------|
| FR-\* | PRD 5절 | 서비스 기능 요구사항 |
| NFR-\* | PRD 5.5절 | 서비스 비기능 요구사항 |
| POL-M\* | detailed-spec 5절 | 서비스 제품 정책 (M = mockspec. 사용자 정책 POL-###과 접두로 구분) |
| J\* / T\* / R\* | detailed-spec 7절 / technical-spec 9.2절 / PRD 8절 | 사용자 여정 / WBS / 리스크 |

## 2. 산출물(기획서 HTML) 섹션 구조

뷰어 템플릿이 렌더하는 표준 구조. 템플릿은 서비스가 관리하므로 이 구조의 개선은 재내보내기로 모든 프로젝트에 소급 적용된다.

```
1. 헤더 (표지 = 타이틀 영역)                        [S1]
   - 프로젝트명, 생성 일시, 장면 수 / 어노테이션 수
2. 프로세스 흐름도                                 [구현: 2026-07-12, 기본 접힘: 2026-08-05]
   - scenes + transitions 그래프의 자체 SVG 렌더 (Mermaid → 자체 SVG 변경: s1-kickoff 11절 7차)
   - 노드 라벨 = 편집: "SCR-### 장면제목" / 산출물: "headerTitle ?? title" (SCR 미노출, 이슈 #38)
   - 사람이 입력한 전이만 그린다 — 비어 있으면 섹션 생략 (추론으로 채우지 않음)
   - **기본 접힘** (s1-kickoff 11절 19차, 이슈 #86). 화면 이동의 주 수단은 화면영역 하단의
     전/후 컨트롤이고, 흐름도는 **비순차 점프(노드 클릭) 전용**이다. 접힘 상태에서도 제목 행과
     토글은 남아 언제든 펼칠 수 있다. 이 분리 덕분에 "전이가 없으면 생략"을 유지해도
     이동 수단이 사라지지 않는다 — 흐름도를 유일한 네비로 삼으면 전이 미입력 프로젝트가
     2번째 화면부터 도달 불가가 된다
3. 장면 섹션 (SCR 코드 순이 아니라 order 순)        [S1]
   - 각 장면: 스테이지 헤더 + stateNote + 캡처 스냅샷 (마커 오버레이) + 어노테이션 목록
   - **레이아웃 = 화면영역 + 디스크립션 2컬럼** (s1-kickoff 11절 19차, 이슈 #86).
     좌측 화면목록은 두지 않는다 — 화면기획서 관례이자, 그 폭이 화면영역으로 가야 목업이
     한눈에 들어온다. 화면은 한 번에 하나만 노출한다
   - **화면 이동 = 화면영역 하단 전/후 컨트롤** `[← 이전] [현재/전체] [다음 →]`.
     첫 화면에서 [이전], 마지막에서 [다음]은 비활성. order 순을 따른다
   - **캡처는 화면영역에 맞춰 축소(fit)** — 컨테이너를 넘으면 배율을 적용하되 **1.0을 넘겨
     확대하지 않는다.** 배율은 iframe과 마커 레이어를 함께 감싸는 요소에 걸어 마커 정합을 지킨다.
     **테두리를 가진 바깥 상자는 배율 밖에 둔다** — 안에 넣으면 `box-sizing: border-box` 탓에
     콘텐츠 상자가 테두리만큼 작아져 축소본이 잘린다 (s1-kickoff 11절 19차)
   - **페이지 헤더 밴드** [이슈 #38, 구현: 2026-07-24] — 장면 상단(스테이지 헤더 위). `pageSectionLabel`·`headerTitle` 중 하나라도 값이 있으면 렌더, 없으면 생략(흐름도 섹션과 동일 정책). 밴드 내용: 섹션 라벨(있을 때만) + 페이지 타이틀(`headerTitle`, 있을 때만). 브랜드 로고는 v1 제외.
   - **제목 슬롯**: 산출물(export)에서는 `headerTitle ?? title`을 항상 렌더. 편집 화면에서는 `SCR-### {title}` 유지(아래 4절).
   - **산출물 SCR 숨김(방향 2)**: export HTML에서는 `SCR-###` 표시 코드를 사이드바·스테이지·흐름도·전이 링크 등 **어느 곳에도 노출하지 않는다**. 내부 참조·편집 네비에서만 SCR가 살아 있다.
   - 전이가 있는 어노테이션: "→ {대상 장면 제목} 보기" 링크 (export는 SCR 없이 제목만) [구현: 2026-07-12, export 표기 개정: 2026-07-24]
4. 정책정의서                                      [S2]
   - 프로젝트에 등록된 POL-### 항목 전체 (코드·제목·본문)
   - 어노테이션의 policyRefs 뱃지 클릭 시 이 섹션의 해당 항목으로 이동
5. 부록                                           [S1]
   - 생성 도구·버전, spec version, 캡처되지 않은 장면 목록(경고)
```

S1 뷰어는 **1·3·5를 항상 렌더하고, 전이가 하나라도 있으면 2(흐름도)도 렌더한다** (현행 detailed-spec 4.1절의 화면영역+디스크립션 레이아웃이 3번 섹션의 구현이다). 2번은 2026-07-12 전이 착수로 구현 — 헤더 아래 접을 수 있는 섹션이고 **2026-08-05부터 기본 접힘**이다. 4번(정책정의서)은 데이터(Policy 엔티티)가 생길 때 추가하되, 섹션 번호와 순서는 지금 확정한다.

## 3. 정책(Policy) 참조 규범

### 3.1 S1 — 자유 텍스트 참조

- `Annotation.policyRefs: string[]`에 자유 기입 (예: `"POL-014"`, `"전사 개인정보 정책 3절"`)
- 뷰어는 뱃지로 표시만 한다. 링크·검증 없음
- 용도: 기존 사내 정책 문서 체계와의 연결 고리 유지

### 3.2 S2 — 프로젝트 내 정책정의서

- `Policy { id: "pol_"+nanoid(10), code: "POL-###", title, body }` 엔티티 도입 (technical-spec 2.2절)
- 편집 패널에 정책 등록 UI 추가, `policyRefs`가 프로젝트 내 POL 코드와 일치하면 산출물에서 상호 링크
- 일치하지 않는 자유 텍스트도 계속 허용 (외부 문서 참조용) — 뱃지만 표시

## 4. 표기 규칙 (뷰어·패널 공통)

| 항목 | 규칙 |
|------|------|
| 장면 표기 (편집) | `SCR-001 로그인` (코드 + 공백 + 제목). 코드는 보조색·고정폭 |
| 장면 표기 (산출물) | `SCR-###` 미노출. 제목 슬롯 = `headerTitle ?? title` (이슈 #38 방향 2). 페이지 헤더 밴드가 있으면 섹션 라벨은 밴드에만 표시 |
| 페이지 헤더 밴드 | `pageSectionLabel`(예: `03 화면상세`)·`headerTitle`(기획서 페이지 타이틀, `title`과 별개). 둘 중 하나라도 있으면 밴드 렌더. 사람 입력만 — 추론·기본값 없음 |
| 어노테이션 마커 | 원형 배지에 장면 내 번호. 툴팁에 title |
| 결번 | 목록에서 건너뛴 번호는 표시하지 않음 (①③④처럼 자연스럽게 비움). "②는 삭제됨" 같은 표기 금지 |
| 위치 불확실 마커 | 점선 테두리 + 툴팁 "요소를 찾지 못해 마지막 위치에 표시됨" |
| 날짜 | ISO 8601 → 표시할 때 `2026-07-06 14:30` 형식 |
| policyRefs 뱃지 | 각진 뱃지, 프로젝트 내 POL과 일치 시 링크 스타일 [S2] |
