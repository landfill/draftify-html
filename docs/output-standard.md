## 1. ID 체계

### 1.1 두 층위: 내부 ID와 표시 코드

| 층위 | 형식 | 용도 | 사용자 노출 |
|------|------|------|------------|
| **내부 ID** | `prj_`/`scn_`/`ann_`/`pol_` + nanoid(10) | 참조 무결성, API, 저장 | 노출 안 함 |
| **표시 코드** | `SCR-###`, `POL-###`, 장면 내 번호 ①②③ | 사람이 읽고 부르는 이름 (기획서 본문, 회의, 리뷰 코멘트) | 뷰어·패널에 표시 |

내부 ID는 절대 바뀌지 않고, 표시 코드는 사람의 참조 습관을 위해 존재한다. 두 층위를 섞지 않는다.

### 1.2 표시 코드 정의

| 코드 | 대상 | 부여 규칙 |
|------|------|----------|
| **SCR-###** | 장면(Scene) | 프로젝트 내 **생성 순** 3자리 (SCR-001부터). 장면 생성 시 확정되어 `Scene.code`에 저장. **재부여·재사용 금지** — 장면을 삭제해도 그 번호는 영구 결번. order(정렬)를 바꿔도 코드는 불변 |
| **①②③ (장면 내 번호)** | 어노테이션(Annotation) | 장면 내 1부터 자동 부여. 삭제 시 재부여 금지 (빈 번호 허용) |
| **SCR-###-N** | 어노테이션 전역 참조 | 장면 코드 + 번호 조합 (예: `SCR-003-2`). 장면을 넘어 어노테이션을 지칭할 때 사용 (전이 설명, 정책 본문, 리뷰 코멘트) |
| **POL-###** | 정책(Policy) [S2] | 프로젝트 내 정책정의서 항목. 생성 순 3자리, 재부여 금지. S1에서는 `policyRefs`에 자유 텍스트로 기입만 (외부 정책 문서 참조 포함) |

재부여 금지의 이유는 단 하나: **이미 공유된 산출물과의 참조 불일치 방지.** 기획서는 메일·위키로 퍼지는 아카이브 문서이므로, 한번 나간 코드가 다른 것을 가리키게 되면 안 된다.

### 1.3 서비스 문서용 ID (산출물과 구분)

혼동 방지를 위해 명시한다. 아래는 mockspec **서비스 자체를 만들기 위한** 문서 ID이며, 사용자의 기획서(산출물)에는 등장하지 않는다:

| 코드 | 정의 위치 | 대상 |
|------|----------|------|
| FR-\* | PRD §5 | 서비스 기능 요구사항 |
| NFR-\* | PRD §5.5 | 서비스 비기능 요구사항 |
| POL-M\* | detailed-spec §5 | 서비스 제품 정책 (M = mockspec. 사용자 정책 POL-###과 접두로 구분) |
| J\* / T\* / R\* | detailed-spec §7 / technical-spec §9.2 / PRD §8 | 사용자 여정 / WBS / 리스크 |

## 2. 산출물(기획서 HTML) 섹션 구조

뷰어 템플릿이 렌더하는 표준 구조. 템플릿은 서비스가 관리하므로 이 구조의 개선은 재내보내기로 모든 프로젝트에 소급 적용된다.

```
1. 헤더 (표지)                                    [S1]
   - 프로젝트명, 생성 일시, 장면 수 / 어노테이션 수
2. 프로세스 흐름도                                 [S2]
   - scenes + transitions 그래프의 Mermaid 렌더
   - 노드 라벨 = "SCR-### 장면제목", 간선 라벨 = 전이 조건
   - 사람이 입력한 전이만 그린다 — 비어 있으면 섹션 생략 (추론으로 채우지 않음)
3. 장면 섹션 (SCR 코드 순이 아니라 order 순)        [S1]
   - 각 장면: "SCR-### {제목}" + stateNote
   - 동결 스냅샷 (마커 오버레이) + 어노테이션 목록 (번호·title·description·policyRefs 뱃지)
   - 전이가 있는 어노테이션: "→ SCR-### 보기" 링크    [S2]
4. 정책정의서                                      [S2]
   - 프로젝트에 등록된 POL-### 항목 전체 (코드·제목·본문)
   - 어노테이션의 policyRefs 뱃지 클릭 시 이 섹션의 해당 항목으로 이동
5. 부록                                           [S1]
   - 생성 도구·버전, spec version, 동결되지 않은 장면 목록(경고)
```

S1 뷰어는 1·3·5만 렌더한다 (현행 detailed-spec §4.1의 사이드바+중앙+패널 레이아웃이 3번 섹션의 구현이다). 2·4는 데이터가 생기는 S2에서 추가하되, 섹션 번호와 순서는 지금 확정한다.

## 3. 정책(Policy) 참조 규범

### 3.1 S1 — 자유 텍스트 참조

- `Annotation.policyRefs: string[]`에 자유 기입 (예: `"POL-014"`, `"전사 개인정보 정책 §3"`)
- 뷰어는 뱃지로 표시만 한다. 링크·검증 없음
- 용도: 기존 사내 정책 문서 체계와의 연결 고리 유지

### 3.2 S2 — 프로젝트 내 정책정의서

- `Policy { id: "pol_"+nanoid(10), code: "POL-###", title, body }` 엔티티 도입 (technical-spec §2.2)
- 편집 패널에 정책 등록 UI 추가, `policyRefs`가 프로젝트 내 POL 코드와 일치하면 산출물에서 상호 링크
- 일치하지 않는 자유 텍스트도 계속 허용 (외부 문서 참조용) — 뱃지만 표시

## 4. 표기 규칙 (뷰어·패널 공통)

| 항목 | 규칙 |
|------|------|
| 장면 표기 | `SCR-001 로그인` (코드 + 공백 + 제목). 코드는 보조색·고정폭 |
| 어노테이션 마커 | 원형 배지에 장면 내 번호. 툴팁에 title |
| 결번 | 목록에서 건너뛴 번호는 표시하지 않음 (①③④처럼 자연스럽게 비움). "②는 삭제됨" 같은 표기 금지 |
| 위치 불확실 마커 | 점선 테두리 + 툴팁 "요소를 찾지 못해 마지막 위치에 표시됨" |
| 날짜 | ISO 8601 → 표시할 때 `2026-07-06 14:30` 형식 |
| policyRefs 뱃지 | 각진 뱃지, 프로젝트 내 POL과 일치 시 링크 스타일 [S2] |
